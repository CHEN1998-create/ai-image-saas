# 鉴权与数据库模块实现计划

## Context（为什么做这件事）

前端骨架（21 个页面 + mock-data）已验证可跑。现在按用户要求**按顺序逐模块**补两个底层能力：

1. **鉴权**：注册 / 登录 / 角色区分（admin vs user）。当前 `login`、`register` 是静态 `form action="/app/generate"`，`(dashboard)` 和 `admin` 布局都没有任何 session 校验，`components/app/sidebar.tsx` 底部用户卡用的是 `lib/mock-data.ts` 里的静态 `currentUser`。
2. **数据库**：PRD 第 6 节 12 张表的"数据表创建"+ 各表的"读写接口"。

### 关键选型（已与用户确认）

- **运行时形态**：纯前端 mock 层。不连真实 Supabase，用 JSON 文件 + httpOnly cookie 在本地模拟用户表、会话、业务表。能跑通端到端流程、注册的用户可持久化（重启 dev server 不丢），但明确不是生产级安全。
- **migration 工件**：仍把 PRD 第 6 节 SQL 转成 `supabase/migrations/*.sql`，作为将来切真实 Supabase 时的参考（当前不 apply）。
- **接口形态**：用户在选项里选了 "Other" 未填文字。我**解读为**：**读用 Server Component 直查 lib/db（RSC，无 HTTP 跳）+ 写用 Route Handlers（`app/api/*`，client fetch）**。这是 mock 层最自然的形态，且保留了 PRD 第 9 节的 API 形状，将来换真实 Supabase 时只换 lib 内部、页面和路由形状不变。**若你想要别的（如全部 Route Handler、或全 Server Actions），在 review 时告知即可改。**

约束：**只增量加功能，不动已验证的视觉与页面布局**。深色 Midjourney 风格、紫红品牌色、三入口路由前缀 `/www` `/app` `/admin` 保持不变。

## 模块 1：鉴权（注册 / 登录 / 角色区分）

### 1.1 mock 会话与用户存储

**新建 `lib/auth/`（server-only，Node runtime）：**

- `lib/auth/types.ts` — `AuthUser = { id, email, name, avatar, role: 'user'|'admin', plan, points, createdAt }`。对齐 `lib/mock-data.ts` 的 `currentUser` 字段，**新增 `role`**。
- `lib/auth/store.ts` — JSON 文件持久化的用户表：`.mock-db/users.json`。用 `fs/promises` read-modify-write。首次访问时 seed：
  - `aria@lumen.art` / `password`（role `user`，plan `standard`，points 6420）—— 对齐现有 `currentUser`，保证已有页面视觉不变。
  - `admin@lumen.art` / `admin123`（role `admin`）。
  - 函数：`findUserByEmail` / `getUserById` / `createUser` / `updateUser`。
- `lib/auth/password.ts` — 用 `node:crypto` 的 `scrypt` 做哈希+校验。注释标明"mock 级，非生产栈"。
- `lib/auth/session.ts` — cookie 名 `lumen_session`。`createSession(user)` 用 `node:crypto` HMAC-SHA256 签名 payload `{ uid, role, exp }` 后 base64；`getSession()` 读 cookie → 验签 → 查 store 返回完整 `AuthUser`；`destroySession()` 清 cookie。`maxAge` 7 天，`httpOnly` + `sameSite=lax` + `path=/`。
- `lib/auth/index.ts` — 聚合：`register(email,password,name)` / `login(email,password)` / `getCurrentUser()` / `requireUser()`（无 session 抛 `redirect('/app/login')`）/ `requireAdmin()`（role≠admin 抛 `redirect('/app')`）/ `logout()`。

### 1.2 Route Handlers（写动作 + /api/me）

新建 `app/api/`：
- `app/api/auth/register/route.ts` — POST：校验邮箱/密码 → `register()` → `createSession()` → 返回 `{ user }`。
- `app/api/auth/login/route.ts` — POST：`login()` → `createSession()` → 返回 `{ user }`。
- `app/api/auth/logout/route.ts` — POST：`destroySession()`。
- `app/api/me/route.ts` — GET：`getCurrentUser()`，无 session 返回 401。

### 1.3 改造登录/注册页

- `app/app/(auth)/login/page.tsx` 改 `"use client"`：`useState` 管 email/password/loading/error，`fetch('/api/auth/login')`，成功 `router.push('/app/generate')`，失败显示错误。**视觉保持不变**（同样的 GitHub/Google 按钮、分隔线、表单布局）。
- `app/app/(auth)/register/page.tsx` 同理改 client，调 `/api/auth/register`。
- 第三方登录按钮保留但标"暂未接入"（disable 或点击 toast），避免假跳转。

### 1.4 路由守卫 middleware

新建 `middleware.ts`（根目录，Edge runtime）。matcher: `/app/:path*`、`/admin/:path*`。
- 读 `lumen_session` cookie。**Edge 不用 fs、不做 HMAC 验签**（node:crypto 在 Edge 不可用），只做轻量解码 base64 payload 取 `{ uid, role, exp }`。
- `/app/login`、`/app/register` 放行；其余 `/app/*` 无 cookie 或 exp 过期 → `redirect('/app/login')`。
- `/admin/*` 无 cookie → `/app/login`；有 cookie 但 role≠admin → `redirect('/app')`。
- 注释标明：**权威 role 校验在 server 侧 `requireAdmin()` 二次校验**，middleware 只做粗粒度拦截（mock 级，cookie 可被本地伪造，不影响演示）。

### 1.5 布局接 session + 角色区分

- `app/app/(dashboard)/layout.tsx` 改 async server component：调 `requireUser()` → 取 `AuthUser` → 作为 prop 传给 `Sidebar`。
- `components/app/sidebar.tsx`：底部用户卡从 prop 取（替换 `import { currentUser } from "@/lib/mock-data"`），显示真实登录用户头像/名字/积分。若 `role==='admin'`，在用户卡旁加一个"进入后台"链接到 `/admin`。
- `app/admin/layout.tsx` 改 async server component：调 `requireAdmin()`。
- `components/app/mobile-nav.tsx` 同步用 prop（如有用户信息展示）。

### 1.6 角色区分落地

- 两个 seed 账号体现角色区分：普通用户登 `/app` 进工作台；管理员登 `/admin` 进后台，也能访问 `/app`。
- `app/app/(dashboard)/settings/page.tsx`（当前 server component，import `currentUser`）改读 `getCurrentUser()`，展示真实角色/套餐/绑定信息。

## 模块 2：数据库（数据表创建 + 读写接口）

### 2.1 数据表创建（migration 工件）

新建 `supabase/migrations/`：
- `0001_init.sql` — PRD 第 6 节 12 张表（profiles / generation_tasks / generated_images / billing_records / point_records / api_call_logs / provider_call_logs / system_health_checks / subscription_plans / shared_posts / post_likes / post_comments）。相对 PRD 增强：
  - PK 用 `gen_random_uuid() default`。
  - `profiles.id uuid references auth.users(id) on delete cascade`。
  - `created_at timestamptz default now()`。
  - 外键：`generation_tasks.user_id` → `profiles(id)` 等。
  - 索引：各表的 `(user_id, created_at desc)`。
- `0002_rls.sql` — RLS：用户只能 select 自己行；admin 全量。`is_admin()` helper 用 `exists(select 1 from profiles where id=auth.uid() and role='admin')`。
- `0003_triggers.sql` — 新 auth 用户注册时自动 insert 一条 `profiles`（role 默认 'user'，plan 'free'，points 0）。
- 顶部注释标明：**参考工件，当前 mock 运行时不 apply；切真实 Supabase 时 `supabase db reset` 即可。**

### 2.2 mock 数据库 + 读写接口（lib/db）

新建 `lib/db/`（server-only）：
- `lib/db/types.ts` — TS 类型，对齐 mock-data 已有类型（`Plan`/`GalleryImage`/`GenerationTask`/`PointRecord`/`Post`/`Comment` 等）并补 admin 相关类型。
- `lib/db/store.ts` — JSON 文件持久化：`.mock-db/{gallery,tasks,points,posts,billing,plans,admin_*.json}`。首次访问 seed 自 `lib/mock-data.ts`，保证已有页面视觉零变化。read-modify-write + 简单互斥（promise 队列）。
- `lib/db/reads.ts` — `getGallery(userId)` / `getGenerationTasks(userId)` / `getPoints(userId)` / `getPointRecords(userId)` / `getPosts()` / `getPost(id)` / `getPlans()` / `getBillingRecords(userId)` + admin: `getAdminOverview()` / `getAdminUsers()` / `getAdminTasks()` / `getAdminPosts()` / `getAnalytics()` / `getObservability()` / `getAdminOrders()`。
- `lib/db/writes.ts` — `createGenerationTask(userId, input)` / `addPointRecord(userId, delta, source)` / `deleteGalleryImage(id)` / `toggleFavorite(id)` / `publishPost(userId, imageId, caption)` / `togglePostLike(postId, userId)` / `addComment(postId, userId, content)` / `repostPost(postId, userId)` / `checkIn(userId)`。写操作会级联更新 `points`、`users.points`。

### 2.3 Route Handlers（写 + 必要读，对齐 PRD 第 9 节）

新建 `app/api/`（鉴权已建 4 个，这里补业务）：
- 读（client 用）：`/api/points`、`/api/gallery`、`/api/billing/plans`、`/api/billing/records`、`/api/posts`、`/api/posts/:id`。
- 写：`/api/points/check-in`、`/api/generations`（POST）、`/api/gallery/:id`（DELETE）、`/api/gallery/:id/favorite`（PATCH）、`/api/posts`（POST）、`/api/posts/:id/likes`（POST/DELETE）、`/api/posts/:id/comments`（POST）、`/api/posts/:id/repost`（POST）。
- admin 读：`/api/admin/overview`、`/api/admin/users`、`/api/admin/tasks`、`/api/admin/posts`、`/api/admin/analytics/*`、`/api/admin/billing`。
- 每个 handler 顶部调 `requireUser()` 或 `requireAdmin()` 做权威鉴权。

### 2.4 页面接入（增量、低风险）

按"server 直查 / client fetch"二分：
- **Server Component 页（当前就是 server，零风险改 import）** 直查 `lib/db`：
  - `app/app/(dashboard)/settings/page.tsx`（改读 `getCurrentUser()`，已在 1.6）。
  - `app/app/(dashboard)/posts/[id]/page.tsx`（`getPost` + `getComments`）。
  - `app/admin/page.tsx`、`app/admin/plans/page.tsx`、`app/admin/analytics/page.tsx`、`app/admin/observability/page.tsx`（调 admin reads）。
- **Client Component 页**：保持 client 不动，仅把顶部的 mock-data import 换成 `useEffect` fetch 对应 Route Handler + 同样的初始 loading/空态。本次只接入**鉴权链路最相关**的：
  - `app/app/(dashboard)/generate/page.tsx` — 提交改 `fetch('/api/generations')`，扣积分、写 task、返回结果；当前 mock `setTimeout` 逻辑保留作"生成中"过渡，成功后用接口返回的图替换。
  - `app/app/(dashboard)/points/page.tsx` — 改 fetch `/api/points`。
  - `app/app/(dashboard)/gallery/page.tsx` — 改 fetch `/api/gallery`。
- 其余 client 页（explore/billing/admin users/tasks/posts/billing）**保留 mock-data 直引**，本次不动，保证不回归视觉。接入模式确定后可后续按同模式逐页迁移。

`.mock-db/` 加入 `.gitignore`。
